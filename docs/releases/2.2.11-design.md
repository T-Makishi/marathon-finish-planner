# 2.2.11 印刷プレビューの末尾白紙ページ修正設計

## 現象と原因

- すべての `.sheet` に強制改ページを指定し、最後だけ `.sheet:last-child` で解除している。
- 実際の印刷HTMLでは最後の用紙要素の後に印刷検証用の `script` があるため、用紙は `last-child` にならない。
- このため最終用紙の後にも改ページが残り、Safari・Chromeの印刷プレビューで末尾に白紙が追加される。
- さらにA4と同じ297mmぴったりの用紙高は、ブラウザーのmmからピクセルへの丸めで境界を超える可能性がある。

## 修正

- 最終用紙の判定を `last-of-type` に変更し、後続のスクリプトに影響されず改ページを解除する。
- 印刷時の用紙要素だけ高さを296.5mmにし、0.5mmの丸め誤差余白を確保する。
- A4のページ指定、100％印刷、カード・折り線・切り取り線・補足資料の寸法と配置は維持する。
- 印刷用紙の横幅を210mmに固定し、横方向の意図しないはみ出しを防ぐ。

## 検証

- 複数ページと1ページのHTMLで、最終用紙だけ改ページ解除の対象になることを検査する。
- 印刷CSSに296.5mmの安全余白と210mmの用紙幅があることを検査する。
- ChromeのPDF出力で、設計ページ数と実PDFページ数が一致することを1ページ・複数ページで確認する。
- 既存回帰テスト、型検査、Web/iOSビルド、公開サイトの印刷HTMLを確認する。
